# Vermi Veda HR Module — Validation Checklist

## Scope
Feature branch: `feature/hr-module`
This checklist is for pre-deployment validation. No production migration or deployment is implied.

## Database / migration
- [ ] Confirm current employee codes are unique and nonblank.
- [ ] Apply reviewed HR migration only after approval.
- [ ] Verify employee-code sequence/trigger produces the next `VV###` code without collision.
- [ ] Verify onboarding table, status indexes, RLS policies, and private storage bucket.
- [ ] Verify HR/admin roles exist in both required profile tables for authorized users only.

## Employee Master
- [ ] HR/Admin can list, search by name/code/mobile/email/department, filter by status.
- [ ] HR/Admin can add and edit an employee.
- [ ] Employee code is generated by database trigger on insert.
- [ ] Email displays correctly and is included in CSV export.
- [ ] CSV export neutralizes formula-like values beginning with whitespace then =, +, -, or @.
- [ ] Non-HR user cannot add/edit employee data.

## Onboarding document verification
- [ ] Applicant record appears in HR verification list.
- [ ] HR can open document preview via a short-lived signed URL.
- [ ] HR can verify/reject documents; rejection requires remarks.
- [ ] Required docs: Aadhaar front, Aadhaar back, PAN, bank proof, employee photo.
- [ ] Approval is blocked until all required documents are verified.
- [ ] Rejected applications cannot be approved.
- [ ] Approval creates one employee only and marks request approved atomically.
- [ ] Employee documents metadata is copied to employee document table.

## FE account provisioning
- [ ] Approved employee with email can provision an FE account.
- [ ] Non-HR/Admin caller is rejected by Edge Function.
- [ ] Unapproved employee or missing email is rejected.
- [ ] Duplicate/concurrent provisioning attempts are blocked.
- [ ] Failed provisioning leaves recoverable status and no orphan Auth user/profile.
- [ ] Stale pending status recovery works only after the intended timeout.
- [ ] Temporary password is delivered securely and is not retained in logs.
- [ ] FE can sign in and is forced to change temporary password.
- [ ] Password-change RPC clears the force-change flag for the signed-in user only.

## Release gate
- [ ] Run end-to-end tests in a non-production environment.
- [ ] Review SQL and RLS policies.
- [ ] Confirm backups and rollback plan.
- [ ] Obtain explicit approval before applying migrations or deploying.
